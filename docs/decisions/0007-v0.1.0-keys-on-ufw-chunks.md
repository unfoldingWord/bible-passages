# 0007: v0.1.0 keys are built on the UFW chunk files

- **Status:** accepted
- **Date:** 2026-11-05
- **Decided by:** the maintainer, on #244 (decision 2 there). Settles open
  decision 8 (`../schema.md`) for v0.1.0. The content team's ruling (#4) is
  still asked for.

## Decision

1. **v0.1.0's segment boundaries, and so its segment keys, come from the
   UFW chunk files** (`Door43-Catalog/versification`, `bible/ufw/chunks/`,
   pinned at `af14923`), split at each BSB pericope start, as
   `data/structure/` is built today.
2. **They are no longer provisional for v0.1.0.** The plan said keys would
   not be released until the chunk source was settled
   (`../scoping/plan.md`, 1 Nov gate). This decision settles it for the
   first tag; the keys v0.1.0 ships are permanent from then on (ADR
   [0001](0001-span-keys.md)).
3. **The list still goes to the content team.** The 1,184 places where
   ULT's `\ts\*` markers and the UFW chunk files disagree are still put to
   them for a ruling (#4).
4. **If they later rule for ULT at some places**, those boundaries move in
   a later release. Each moved span gets its own key, and each key that
   lost its span is retired with a successor in `data/retired-keys.json`
   (ADR 0001). No released key is reused or given a different span, and no
   released tag is changed.

## Evidence

- **The content team has not answered.** #4 has 0 comments and was last
  updated on 28 Oct 2026 (read on 5 Nov with `gh issue view 4`). It is
  unassigned.
- **1,184 differences.** #4's body: 622 chunk starts only in the UFW files
  and 562 only in ULT (`en_ult` at `04e15203`, versification at `af14923`),
  most in 2SA (162), EXO (161), 1SA (129), PSA (114) and NEH (103).
  Re-derived on 5 Nov by counting the rows of
  [`../scoping/ts-vs-ufw.tsv`](../scoping/ts-vs-ufw.tsv) by its `in` column
  (`awk`): 622 `UFW only`, 562 `ULT only`, 1,184 in all; the same five
  books lead with the same counts.
- **The build already uses the UFW chunk files.** `data/structure/` holds
  66 books, 3,016 pericopes and 13,770 segments (counted with a Node script
  over `data/structure/*.json` on 5 Nov, base `3b4cc37`), the totals in
  `../scoping/sizing.md` (13,608 chunks + 162 splits). Nothing has to be
  rebuilt for this decision.
- **Nothing is released yet.** `data/retired-keys.json` has no rows, and
  `git ls-remote --tags origin` printed no tags (5 Nov).

## Why

- ADR 0001 says the chunk source must be settled before the first release,
  because changing it later retires keys. Waiting for #4 would hold v0.1.0
  with no date for an answer.
- The UFW chunk files are what the dataset, its sizing and its 6 drafted
  books are built on. With ULT's markers the splits would be 165 instead of
  162, and the segment count would change with them
  (`../scoping/sizing.md`).
- ADR 0001 already gives a safe path for a later ruling: new keys and
  retirement records, never a changed key. Translators' recordings keep
  their keys.

## Cost, accepted

Any place the content team later rules for ULT retires the keys there.
Under ADR 0001 a retired key's titles stay stored. Only resize and split
write a copy onto the named successor, and that copy is `unreviewed`. Merge
and move-back write no copy. Each new key needs its title drafted, checked
or reviewed again.

The size of that is unknown until the ruling. Dropping a UFW-only chunk
start merges two segments and retires two keys; adding a ULT-only start
splits one segment and retires one key. If all 1,184 places went to ULT and
none shared a segment, that is 622 × 2 + 562 × 1 = 1,806 retired keys (an
upper bound by arithmetic, not measured). Places next to each other share
segments, and a chunk start on either list that falls on a BSB pericope
start is a segment boundary either way, so the real number is lower.

Which version number such a release takes follows `../schema.md`,
"Releases" (major for keys dropped). Those rules are assumed from the
tc-mobile contract and not yet checked by the workflow.

## Rejected

- **Wait for the content team before tagging.** No answer in 8 days (28 Oct
  to 5 Nov), and the 16 Nov date (#13) would slip with no gate to decide it.
- **Switch to ULT's `\ts\*` markers now.** No one has ruled for ULT, and it
  would move segment boundaries at up to 1,184 places, including in the 6 drafted books
  (in Titus, at 1:14), and redo their titles for a choice the content team
  has not made.

## Changes

- `../schema.md`, open decision 8: decided for v0.1.0; the ruling on #4 is
  still asked for.
- ADR 0001's sentence that the chunk source must be settled before the first
  release is met by this decision.
